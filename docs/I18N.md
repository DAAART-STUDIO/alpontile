# Internationalization

## Supported languages

The website supports:

- Italian — `it.json`
- English — `en.json`
- German — `de.json`

Italian is the primary language for the restaurant's local communication.

## Translation files

```text
data/i18n/
├── de.json
├── en.json
└── it.json
```

The files use the same translation-key structure.

## Rules

When a public-facing HTML translation key is changed:

1. identify the key used by the HTML;
2. update the Italian value;
3. update the English value;
4. update the German value;
5. preserve the key name;
6. verify that no donor text remains.

Do not delete a key simply because it is not currently visible without checking its usage in HTML and JavaScript.

## Translation quality

Translations should be natural for a hospitality website.

### Italian

Italian should read as native restaurant communication for Italy, not as a literal translation from English.

### English

English should be concise, natural and suitable for international visitors.

### German

German should be natural for German-speaking visitors to Lake Garda and should avoid machine-translation phrasing.

## Content accuracy

Translation does not authorize changing facts.

Names, addresses, telephone numbers, email addresses, menu items, prices, services and event claims must remain factually consistent across languages.

## Dynamic loading

The existing JavaScript i18n implementation is responsible for loading and applying translation data. The implementation is located in:

```text
js/modules/i18n.js
```

The existing mechanism should be preserved.

## QA checklist

Before publishing:

- all three JSON files are valid;
- translation keys are synchronized;
- no donor restaurant names remain;
- no donor URLs remain;
- no mixed-language fragments remain in a translated section;
- restaurant facts are identical in meaning across languages.
